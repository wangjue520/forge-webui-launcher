## 一、这个启动器是什么

一个给 [Stable Diffusion WebUI Forge](https://github.com/lllyasviel/stable-diffusion-webui-forge) 用的**图形界面启动器**（Windows 版）。它把"装环境、下代码、装依赖、配参数、启动"这些命令行操作全部变成了按钮，并且：

- **不需要你提前装 Python**——双击后自动下载便携版 Python 并装进自己的虚拟环境，任何电脑上环境完全一致，绝不碰系统 Python
- **默认部署 Neo 分支**（社区持续维护的新分支，支持新显卡/新参数体系，**推荐**），也支持官方 Classic 版
- **国内网络优化**——按 IP 归属地自动判断：国内走 GitHub / PyPI / HuggingFace 镜像加速，国外直连官方源，下载大文件支持断点续传
- **内置模型下载**（Civitai / 哩布哩布）、模型管理、WD14 反推打标签、生成参数读取等常用工具

> 界面语言为中文，界面由系统自带的 Edge WebView2 渲染（Win10/11 都有，白屏的话看 [FAQ](#q2-窗口白屏或提示-webview2-错误)）。

## 二、安装启动器（有无 Python 都行）

### 方式 A：直接下载（推荐普通用户）

1. 打开本仓库主页 → 绿色 `Code` 按钮 → `Download ZIP`
2. 解压到一个**纯英文、不含空格和括号**的路径，例如 `D:\forge-launcher`
   （路径带中文或 `(1)` 之类后缀是 90% 莫名报错的根源，详见 [FAQ](#q4-部署时提示此时不应有-xxx)）
3. 双击 `start一键启动.bat`

### 方式 B：git 克隆（会 git 的用户）

```bat
git clone https://github.com/wangjue520/forge-webui-launcher.git
cd forge-webui-launcher
start一键启动.bat
```

### 第一次双击会发生什么

不管你的电脑有没有装 Python、装的是什么版本，启动器的行为都一样：
自动下载一个免安装的便携版 Python 3.13（约 45MB）到启动器目录，用它创建
项目内虚拟环境 `.venv`，再自动安装启动器自己的两个依赖（pywebview、requests）。
装依赖时按 IP 归属地自动选源——国内走清华/阿里云镜像，国外走官方源。
只有在便携版下载失败、且系统里恰好有 Python 3.10+ 时，才会退而用系统 Python。

第一次大约需要 1~3 分钟（取决于网络），之后就和其他软件一样秒开。
装完会自动弹出启动器窗口——**此时只是"启动器"装好了，Forge 本体还没有**，继续看下一节。

## 三、从零部署 Forge WebUI（Neo 版）

> 只有第一次需要部署。装好之后日常使用只需要"双击 bat → 点启动"。

1. 打开启动器的 **「环境部署」** 页
2. **分支**保持默认的 `Neo 版（Haoming02 社区维护分支，推荐）` 即可，不用改
   - Neo 是目前仍在持续维护的分支：支持 40/50 系新显卡和新的显存/精度参数体系，插件也持续适配，**新用户一律选它**
   - `常规版/Classic` 是 lllyasviel 的官方原版，已停止更新，只在有特殊兼容性需求时才考虑
3. **安装目录**点「浏览」选一个很空的位置，例如 `D:\forge`
   - 必须是**空目录或不存在**（已有整合包的话也可以选整合包目录，会自动识别并跳过克隆）
   - **强烈建议纯英文路径**：中文/空格/括号都可能导致 torch 等依赖出诡异问题
4. 保持勾选 **「自动下载便携版 Python + Git」**——这样 Forge 用的 Python 3.13 和 Git 也会自动装进 `D:\forge`，不污染系统
5. 点 **「开始部署」**，之后全自动：
   1. 下载便携 Python + Git（GitHub 连不上会自动换加速代理）
   2. 克隆 Forge 源码（Neo 分支）
   3. 检查/创建虚拟环境 venv
   4. 运行 Forge 自带的安装脚本——这一步会下载 torch 等几个 GB 的依赖，**视网速 10 分钟到 1 小时**，随时可点「取消」，下次会接着下（断点续传）
   5. 装完后自动把 WebUI 起起来验证一遍，看到监听地址就说明成功，然后自动停止临时进程、完成收尾

6. 看到日志末尾 **「全部完成！」** + 弹出"部署完成"窗口 → 点「去一键启动」

### 部署失败怎么办

- **日志里出现红色报错**：把报错那几行复制下来去 [FAQ](#十二常见问题-faq) 对照，或提 Issue
- **网络类错误（超时/连接重置/503/504）**：直接再点一次「开始部署」，已下载的部分会自动跳过
- **换过分支或换过 Python 后报版本相关错误**：在「环境部署」页点「检测现有 venv 版本」，按提示删除重建即可

## 四、启动 WebUI

1. 打开 **「一键启动」** 页
2. **WebUI 根目录**确认是刚才部署的目录（部署成功后会自动填好）
3. 点 **「启动」**

- 启动器会实时显示 Forge 的输出日志；出现 `Running on local URL` 后浏览器会**自动打开** WebUI 页面
- 想停止：点 **「停止」**（会把整个进程树干净地杀掉，不会留僵尸进程占端口/显存）
- 直接关启动器窗口时如果 WebUI 还在跑，会弹确认框防止误关

### 启动前的预检弹窗是什么意思

点「启动」时会自动做一轮检查，可能弹出：

| 提示 | 含义 | 建议 |
|---|---|---|
| 端口被占用 | 上次 WebUI 没退干净 | 选「结束并启动」 |
| webui-user.bat 里写死了变量 | 整合包残留的旧配置会覆盖启动器的设置 | 选「清空并启动」 |
| 目录含中文/空格 | 部分依赖有历史 bug | 换纯英文路径 |
| --listen + 允许网页装扩展 | 局域网任何人都能给你的电脑装代码，危险 | 除非必要，关掉一个 |

### 画出第一张图

1. 浏览器打开 WebUI 后，先在左上角「Stable Diffusion checkpoint」下拉里选中一个大模型
   （列表是空的说明还没装模型，先去 [第六节](#六模型放哪里怎么下载) 下一个）
2. 在「提示词」输入框里写画面描述，例如：`1girl, school uniform, cherry blossoms, masterpiece, best quality`
3. 点右侧橙色的「Generate / 生成」按钮，等进度条走完，图片就会出现在下方
4. 图片自动保存在 WebUI 目录下的 `output\txt2img-images\`（Classic 分支是 `outputs\txt2img-images\`）；
   随时可以把图拖进启动器的「图片信息」页，查看这张图当时用的全部参数

## 六、模型：放哪里、怎么下载

### 目录对照（在 WebUI 根目录下）

| 模型类型 | 放到 |
|---|---|
| Checkpoint 大模型 | `models\Stable-diffusion\` |
| LoRA | `models\Lora\` |
| VAE | `models\VAE\` |
| Embedding | `embeddings\` |
| ControlNet | `models\ControlNet\` |
| 放大模型 | `models\ESRGAN\` |

大模型去 [Civitai](https://civitai.com) 或 [哩布哩布](https://www.liblib.art) 下载。

### 用启动器内置下载（推荐）

1. 复制模型网页链接（如 `https://civitai.com/models/xxxx` 或哩布哩布模型页）
2. 打开启动器 **「模型下载」** 页 → 粘贴 → 「获取信息」
3. 选择要下载的文件（有的模型含多个文件/版本）→ 选目标目录 → 「开始下载」
4. 支持断点续传和取消；下载完可自动按哈希从 Civitai 查询并写入信息

> Civitai 有 API Key 的话去「设置」页填上，可以查到自己账号可见的全部资源。哩布哩布的下载接口强制登录，需要在网页登录后从浏览器 Cookie 复制 `usertoken`（设置页有详细引导）。

### 模型管理页能干什么

- 左侧按类别浏览已安装的模型，显示封面/名称/大小
- 单个模型「查询 Civitai 信息」：按 SHA-256 哈希精准匹配，写回触发词、预览图、版本信息
- 「批量查询」：给整页模型一次性补齐信息
- 鼠标悬停列表行可直接「定位 / 复制名 / 复制 lora 调用格式」，不用选中

## 七、WD14 图片反推打标签

训练 LoRA 必备功能。

1. 打开 **「WD14 反推」** 页，首次使用点「加载模型」
   - 模型（约 500MB）会自动从 HuggingFace 镜像下载，国内可用
   - 它使用自己独立的 Python 环境，会自动部署在启动器目录的 `wd14_venv`，不跟 Forge 抢环境
2. 拖入或选择图片 → 点「开始反推」
3. 右侧出现标签和置信度，点标签可复制；勾选「逗号格式」直接得到训练用标签串

## 八、图片信息：读取/编辑生成参数

1. 打开 **「图片信息」** 页，把图片拖进去
2. 自动解析出提示词、负面词、采样器、步数、种子、所用模型、LoRA 等全部参数
3. 支持：

   - **ComfyUI 图片**：workflow 里每个节点（KSampler/Checkpoint/LoRA）单独解析，点击可定位

## 十、启动参数怎么选（显存/精度）

在 **「设置」** 页配置，所有选项都会实时预览生成的命令行参数。

### 分支与参数体系（重要）

Forge 有两套互不兼容的参数体系，启动器按你选的分支自动生成对的：

| 分支 | 显存参数 | 精度参数 |
|---|---|---|
| Neo 版（新版参数） | `--gpu-only` `--highvram` `--normalvram` `--lowvram` `--novram` `--cpu` | `--force-fp16` `--force-fp32`，以及分部件 `--bf16-vae` `--fp8_e4m3fn-unet` 等 |
| Classic / 旧版 Neo | `--always-gpu` `--always-high-vram` `--always-normal-vram` … | `--all-in-fp16` `--all-in-fp32` |

**普通用户全部保持"自动"即可**——Forge 会自动管理显存。只有明确知道自己需求时才动：

- 8G 以下显存爆 OOM：试试「低显存模式」+ VAE 精度选 BF16
- 出图全黑/全灰：「全部使用 FP32」或「VAE 放 CPU」
- 40 系新显卡想用新特性：Neo 分支设置页里有 `--fast-fp16`、`--expandable-segments` 等开关

### 预留显存（Neo 独有）

「预留显存」填 1~2（GB）可以避免 Forge 把显存吃到 100% 导致驱动掉线/桌面卡死，代价是出图略慢一点点。

## 十一、国内网络加速

启动器会自动探测网络环境（结果缓存在配置里，设置页可重新检测）：

| 环节 | 加速方式 |
|---|---|
| GitHub 下载/克隆 | 自动走加速代理（多个候选，失败自动换），原站兜底 |
| pip 安装依赖 | 清华源 → 阿里云源 → 腾讯云源 → 官方源，逐个尝试 |
| torch（几个 GB 那个） | 自动切到清华 pytorch-wheels 镜像 |
| HuggingFace 模型 | 自动切 hf-mirror.com |

设置页的「网络加速」可以强制指定：自动 / 总是用镜像 / 总是用原站。
**挂了代理的用户建议选「自动」或「总是用原站」**，避免代理套代理反而变慢。

> **下载安全**：经代理下载的 Python / Git / 源码都有官方哈希强制校验（SHA256SUMS / 发布正文校验和 + API 摘要交叉核对），Git 安装包还额外验官方数字签名，校验不过会自动换地址重下、全部不符则中止。详见 FAQ Q13。

## 十二、常见问题 FAQ

### Q1：部署卡在"查询最新版本/下载"不动
多半是 GitHub 连不上。等 30 秒看日志里有没有"换下一个地址"——启动器会自动尝试多个加速代理；全部失败就再点一次「开始部署」。也可以先在系统里挂上代理/加速器。

### Q2：窗口白屏或提示 WebView2 错误
系统缺少 Edge WebView2 运行时（极少数精简版系统）。装一下微软官方的即可（免费、无需登录）：
https://developer.microsoft.com/microsoft-edge/webview2/

### Q3：双击 bat 一闪而过 / 提示"不是内部或外部命令"
把启动器放到**纯英文路径**再试；不要从压缩包里直接运行，先完整解压。

### Q4：部署时提示"此时不应有 X"或"XXX 不是内部或外部命令"
安装路径里有 `()`、`&`、`^`、`%`、`!` 等字符（常见：文件夹名带 `(1)`，浏览器重复下载导致的）。
**换纯英文路径**（如 `D:\forge`）重新部署即可，这是 cmd.exe 自身的限制。

### Q5：启动 WebUI 时报错端口被占用 / 7860 被占
上次 WebUI 没退干净。启动器的预检弹窗里选「结束并启动」；或重启电脑。

### Q6：提示 venv 版本不一致 / "Requires-Python >=3.x"
venv 是旧 Python 建的，跟当前分支要求不符。到「环境部署」页点「检测现有 venv 版本」→「删除 venv」，下次启动会自动用正确的 Python 重建。

### Q7：加载模型时报 "hashlib has no attribute file_digest"
老 venv 缺 Python 3.11 的新方法。「环境部署」页点「写入 hashlib 兼容补丁」即可，不用重装。

### Q8：模型下载页提示"用户未登录"（哩布哩布）
哩布哩布的下载接口强制登录。在浏览器登录哩布哩布 → F12 打开开发者工具 → 应用/Cookie → 复制 `usertoken` 的值 → 粘贴到启动器「设置」页的哩布哩布 token 输入框 → 验证。

### Q9：torch 下载到一半断了
直接再点「开始部署」。pip 自带断点续传，已下载的进度不会丢；全部镜像源都会自动轮着试。

### Q10：装好了但网页打不开 / 一直"启动中"
看「一键启动」页的日志：
- 有 `Running on local URL: http://127.0.0.1:7860` 但没自动开浏览器 → 手动复制地址到浏览器
- 红字报错把最后 20 行发 Issue

### Q11：杀软报毒 / 文件被删
便携 Python/Git 是从官方 release 原站下载的，但国产杀软可能误报。把启动器目录和部署目录加入杀软白名单/排除列表后重新部署。

### Q12：如何更新 Forge 本体
「环境部署」页对已有目录再点一次「开始部署」即可——会跳过克隆直接更新依赖、验证可启动。Neo 分支的日常更新也可以直接在 WebUI 网页里用内置的更新功能。

### Q13：走加速代理下载的东西安全吗？会不会被篡改？
启动器对每一个经代理下载的二进制都做了**强制来源校验**，不通过就中止（宁可装不了，也不装来源不可证的东西）：

1. **哈希基准取自官方**：Python 用 python-build-standalone 每个 release 附带的 `SHA256SUMS` 清单，Git 用 git-for-windows 发布正文里的官方校验和，并与 GitHub API 的资产摘要交叉核对——两者不一致直接中止；
2. **解压/执行前强制比对 sha256**：下载完先校验，不符就自动换下一个候选地址重下，全部地址都不符则部署失败；
3. **Git 安装包额外验数字签名**：执行自解压包前用 Windows Authenticode 验证官方签名（Johannes Schindelin / git-for-windows），伪造的二进制过不了系统信任链。

所以如果日志出现"校验失败""签名校验失败""无法获取哈希校验基准"而中止，说明当前网络链路返回的内容与官方发布对不上——先检查代理/加速器是否可信，再重试。

### Q14：提示"没有可用的哈希校验基准，已中止（安全策略）"
是上面的安全机制在起作用的：没能拿到官方校验清单（通常是网络把 GitHub API 和原站都挡住了）。换个网络环境/挂好代理后重新部署即可。

### Q15：拉取代码报 CRYPT_E_NO_REVOCATION_CHECK (0x80092012)，退出码 128
Windows 版 git 用系统 Schannel 建立加密连接，握手前 Windows 要联网向证书颁发机构查询"对方证书有没有被吊销"——这个查询地址在很多网络环境（尤其国内）不可达，连接直接失败，和走不走加速代理无关。启动器部署时会自动关闭便携版 Git 的这个检查（只影响启动器自己那份 git；下载链路另有 sha256/Authenticode 强制校验兜底，不依赖吊销检查）。旧版本启动器或手动装的 git 如遇到此错误，可执行一次：`git config --system http.schannelCheckRevoke false`，然后重新部署。

### Q16：启动 WebUI 报 "ImportError: Failed to initialize: Bad git executable"
便携 Git 不在系统 PATH 里，要靠环境变量指路；而 Forge（Neo）的 webui.bat 会把 GIT 变量的值**原样**拷给 GitPython（`GIT_PYTHON_GIT_EXECUTABLE`）。路径一旦带空格、GIT 值又加了引号，GitPython 会把引号当成路径的一部分去执行，初始化直接失败。新版启动器已改为始终注入未加引号的原始路径；旧版遇到时请升级启动器，或把部署目录换到纯英文无空格路径。

### Q17：装依赖时报 externally-managed-environment / "managed by uv"
你的系统 Python 是 uv 等工具托管的，它按 PEP 668 规则禁止 pip 直接往里装包，所以所有镜像源都会接连报同一个错——这不是网络问题。把启动器更新到最新版即可：新版启动 bat 完全不碰系统 Python——自动下载便携版 Python 并装进项目内 `.venv` 虚拟环境（venv 不受 externally-managed 限制），任何电脑上环境一致。

### Q18：启动器自己怎么更新？
「高级选项」页顶部的「启动器更新」卡片 → 检查更新 → 立即更新 → 重启生效。不用再重新下载整个压缩包：git 克隆安装的只拉取变化的提交，ZIP 安装的走整包覆盖；你的配置、便携 Python/Git、WD14 环境和模型缓存都原样保留。当前版本号显示在侧边栏 logo 下方（规则：2.0.提交数，每次更新自动递增）。

## 1. What is this launcher?

A **graphical launcher** (Windows) for [Stable Diffusion WebUI Forge](https://github.com/lllyasviel/stable-diffusion-webui-forge). It turns the command-line work of "install environment, download code, install dependencies, configure parameters, launch" into buttons, and:

- **No Python required upfront** — it automatically downloads a portable Python and builds its own virtual environment, so the setup is identical on every PC and never touches the system Python
- **Deploys the Neo branch by default** (community-maintained, supports new GPUs and the new parameter system, **recommended**); the official Classic version is also supported
- **Optimized for networks in China** — auto-detects the network environment, uses mirrors for GitHub / PyPI / HuggingFace, and resumes interrupted downloads
- **Built-in tools**: model download (Civitai / liblib), model management, WD14 tagging, generation-parameter viewer, and more

> The UI is in Chinese. It renders with the Edge WebView2 runtime bundled with Windows 10/11 (if you see a white screen, see [FAQ Q2](#q2-white-window-or-a-webview2-error)).

## 2. Installing the launcher (with or without Python)

### Option A: Download ZIP (recommended for regular users)

1. Open the repository page → green `Code` button → `Download ZIP`
2. Extract to a **pure-English path without spaces or parentheses**, e.g. `D:\forge-launcher`
   (Chinese characters or a `(1)` suffix in the path cause ~90% of mysterious errors — see [FAQ Q4](#q4-deploy-fails-with-x-was-unexpected-at-this-time-or-xxx-is-not-recognized))
3. Double-click `start一键启动.bat`

### Option B: git clone (for git users)

```bat
git clone https://github.com/wangjue520/forge-webui-launcher.git
cd forge-webui-launcher
start一键启动.bat
```

### What happens on the first double-click

No matter whether you have Python installed or which version it is, the launcher behaves identically: it downloads a portable Python 3.13 (~45MB) into the launcher folder, creates a project-local virtual environment `.venv` with it, and installs the launcher's own two dependencies (pywebview, requests). The pip source is chosen by your IP's country — mirrors for China, the official PyPI elsewhere. Only if the portable download fails *and* a system Python 3.10+ exists does it fall back to the system Python.

The first run takes 1–3 minutes depending on your network; afterwards it opens instantly like any other app.
When the launcher window pops up, **only the launcher itself is installed — Forge is not yet**. Continue to the next section.

## 3. Deploying Forge WebUI from scratch (Neo)

> You only deploy once. Day-to-day use is just "double-click the bat → press Launch".

1. Open the **Deploy (环境部署)** page in the launcher
2. Keep **Branch** on the default `Neo (community-maintained by Haoming02, recommended)`
   - Neo is the actively maintained branch: it supports newer 40/50-series GPUs and the new VRAM/precision parameter system, and extensions keep adapting to it — **new users should always pick it**
   - `Classic` is lllyasviel's official original; it is no longer updated and only worth considering for special compatibility needs
3. Click **Browse** next to **Install directory** and pick a mostly empty location, e.g. `D:\forge`
   - Must be an **empty or non-existent directory** (if you already have a repackaged bundle there, it will be detected and cloning is skipped)
   - **Strongly recommended: pure-English path** — Chinese/spaces/parentheses can cause bizarre dependency issues with torch etc.
4. Keep **"Auto-download portable Python + Git"** checked — this way Forge's Python 3.13 and Git are installed into `D:\forge` without touching your system
5. Press **Start deploy**. Everything from here is automatic:
   1. Downloads portable Python + Git (automatically switches to an acceleration proxy if GitHub is unreachable)
   2. Clones the Forge source code (Neo branch)
   3. Checks/creates the venv
   4. Runs Forge's own setup script — this downloads several GB of dependencies including torch, **takes 10 minutes to 1 hour depending on your network**. You can press Cancel anytime; next run continues where it left off
   5. After installation, it briefly starts the WebUI to verify everything works, then stops the temporary process and finishes
6. When the log ends with **"全部完成！" (All done!)** and a completion dialog appears → press **Go to launch**

### If deployment fails

- **Red errors in the log**: copy the error lines and check the [FAQ](#12-faq), or open an Issue
- **Network errors (timeout/connection reset/503/504)**: just press Start deploy again — already-downloaded parts are skipped automatically
- **Version-related errors after switching branches or Python**: on the Deploy page use "Detect existing venv version" and follow the prompts to delete and rebuild

## 4. Launching WebUI

1. Open the **Launch (一键启动)** page
2. Confirm **WebUI root directory** points at the directory you just deployed (it's filled in automatically after a successful deploy)
3. Press **Launch (启动)**

- The launcher shows Forge's output in real time; once `Running on local URL` appears, your browser **opens the WebUI automatically**
- To stop: press **Stop (停止)** (kills the whole process tree cleanly — no zombie processes holding ports/VRAM)
- If you close the launcher window while WebUI is still running, a confirmation dialog prevents accidental closes

### What the pre-launch checks mean

Pressing Launch runs a round of checks; you may see:

| Prompt | Meaning | Suggestion |
|---|---|---|
| Port occupied | Previous WebUI didn't shut down cleanly | Choose "Kill and launch" |
| Variables hardcoded in webui-user.bat | Leftover config from a repackaged bundle overrides launcher settings | Choose "Clear and launch" |
| Path contains Chinese/spaces | Some dependencies have historic bugs | Switch to a pure-English path |
| --listen + web extension install allowed | Anyone on your LAN can install code on your PC — dangerous | Unless necessary, turn one off |

### Generating your first image

1. Once the WebUI opens in your browser, pick a checkpoint in the "Stable Diffusion checkpoint" dropdown at the top left
   (if the list is empty you have no models yet — download one first, see [section 6](#6-models-where-they-go-and-how-to-download))
2. Type a description into the prompt box, e.g.: `1girl, school uniform, cherry blossoms, masterpiece, best quality`
3. Press the orange **Generate** button on the right; when the progress bar finishes, the image appears below
4. Images are saved automatically to `output\txt2img-images\` under the WebUI directory (`outputs\txt2img-images\` on Classic);
   you can drag any image into the launcher's Image info page anytime to see every parameter it was generated with

## 10. Choosing launch parameters (VRAM/precision)

Configure on the **Settings (设置)** page; every option previews the generated command-line arguments in real time.

### Branches and parameter systems (important)

Forge has two mutually incompatible parameter systems; the launcher generates the right ones for your branch:

| Branch | VRAM parameters | Precision parameters |
|---|---|---|
| Neo (new system) | `--gpu-only` `--highvram` `--normalvram` `--lowvram` `--novram` `--cpu` | `--force-fp16` `--force-fp32`, plus per-component `--bf16-vae` `--fp8_e4m3fn-unet` etc. |
| Classic / old Neo | `--always-gpu` `--always-high-vram` `--always-normal-vram` … | `--all-in-fp16` `--all-in-fp32` |

**Regular users should leave everything on "Auto"** — Forge manages VRAM by itself. Only tweak when you know what you need:

- OOM with less than 8G VRAM: try "Low VRAM mode" + set VAE precision to BF16
- All-black/all-gray output: "Force FP32" or "VAE on CPU"
- New 40-series GPU features: the Neo settings page has toggles like `--fast-fp16`, `--expandable-segments`

### Reserved VRAM (Neo only)

Setting "Reserved VRAM" to 1–2 (GB) prevents Forge from pushing VRAM to 100% (which can crash the display driver / freeze the desktop) at a small cost in generation speed.

## 11. Network acceleration for users in China

The launcher auto-detects the network environment (the result is cached in the config; you can re-detect on the Settings page):

| Stage | Acceleration |
|---|---|
| GitHub downloads/clones | Auto via acceleration proxies (multiple candidates, auto-switch on failure), with the origin as fallback |
| pip dependencies | Tsinghua mirror → Aliyun → Tencent → official, tried in order |
| torch (the several-GB one) | Auto-switched to the Tsinghua pytorch-wheels mirror |
| HuggingFace models | Auto-switched to hf-mirror.com |

The Settings page can force a mode: Auto / Always mirror / Always origin.
**If you already use a system proxy/VPN, choose "Auto" or "Always origin"** to avoid proxy-over-proxy slowdowns.

> **Download security**: every binary downloaded through a proxy is subject to mandatory origin verification (SHA256SUMS manifests / official release checksums cross-checked against the GitHub API asset digest). The Git installer additionally verifies the official Authenticode signature. Failed verification auto-switches to another mirror; if none match, the deployment aborts. See FAQ Q13.

## 12. FAQ

### Q1: Deployment stuck at "querying latest version / downloading"
Most likely GitHub is unreachable. Wait 30s and watch the log for "trying next address" — the launcher automatically tries multiple acceleration proxies; if all fail, press Start deploy again. You can also enable a system proxy/VPN first.

### Q2: White window or a WebView2 error
Your system is missing the Edge WebView2 runtime (rare, on heavily stripped Windows). Install the official Microsoft runtime (free, no login):
https://developer.microsoft.com/microsoft-edge/webview2/

### Q3: Double-clicking the bat flashes a console / "is not recognized as an internal or external command"
Move the launcher to a **pure-English path**; don't run it from inside the ZIP — extract fully first.

### Q4: Deploy fails with "X was unexpected at this time" or "xxx is not recognized"
The install path contains `()`, `&`, `^`, `%`, `!` etc. (commonly a `(1)` suffix from repeated browser downloads).
**Switch to a pure-English path** (e.g. `D:\forge`) and deploy again — this is a cmd.exe limitation.

### Q5: Port occupied / 7860 already in use when launching
Previous WebUI didn't exit cleanly. Choose "Kill and launch" in the preflight dialog; or reboot.

### Q6: venv version mismatch / "Requires-Python >=3.x"
The venv was created by an older Python and doesn't match the current branch. On the Deploy page use "Detect existing venv version" → "Delete venv"; it will be rebuilt with the correct Python on next launch.

### Q7: "hashlib has no attribute file_digest" when loading models
Old venvs lack a Python 3.11 addition. On the Deploy page press "Apply hashlib compatibility patch" — no reinstall needed.

### Q8: Downloader says "user not logged in" (liblib)
liblib's download API requires login. Log in to liblib in your browser → F12 developer tools → Application/Cookies → copy the `usertoken` value → paste it into the liblib token field on the launcher's Settings page → verify.

### Q9: torch download interrupted halfway
Just press Start deploy again. pip resumes downloads; all mirrors are tried automatically.

### Q10: Installed but the web page won't open / stuck "starting"
Check the log on the Launch page:
- If you see `Running on local URL: http://127.0.0.1:7860` but no browser opened → copy the address into your browser manually
- Red errors → paste the last 20 lines into an Issue

### Q11: Antivirus flags / deletes files
The portable Python/Git are downloaded from official release sources, but some domestic antivirus products false-positive. Add the launcher folder and the deploy folder to the antivirus exclusion list, then deploy again.

### Q12: How to update Forge itself
Just press Start deploy again on the Deploy page with the existing directory — cloning is skipped and dependencies are updated/verified. For Neo, you can also use the built-in updater on the WebUI page for daily updates.

### Q13: Is it safe to download through acceleration proxies? Could files be tampered with?
Every binary downloaded via a proxy goes through **mandatory origin verification**; on failure the launcher aborts (it would rather fail to install than install something with unverifiable origin):

1. **Hash baselines come from the official source**: Python uses the `SHA256SUMS` manifest shipped with every python-build-standalone release; Git uses the official checksum in the git-for-windows release notes, cross-checked against the GitHub API asset digest — any mismatch aborts immediately
2. **Mandatory sha256 check before extraction/execution**: on mismatch it auto-switches to the next candidate address; if none verify, deployment fails
3. **The Git installer additionally verifies the digital signature**: Windows Authenticode validation of the official signature (Johannes Schindelin / git-for-windows) before running the self-extractor — forged binaries can't pass the system trust chain

So if the log shows "verification failed" / "signature check failed" / "no hash baseline available" and aborts, the content returned by your current network path doesn't match the official release — check whether your proxy/VPN is trustworthy, then retry.

### Q14: "No available hash baseline, aborted (security policy)"
The security mechanism above is doing its job: it couldn't fetch the official checksum manifest (usually means the network blocks both the GitHub API and the origin site). Switch to a better network / proper proxy and deploy again.

### Q15: Cloning fails with CRYPT_E_NO_REVOCATION_CHECK (0x80092012), exit code 128
Git for Windows uses the system Schannel for TLS, and before the handshake Windows must query the certificate authority online to check whether the server certificate has been revoked — that CRL/OCSP endpoint is unreachable in many networks (especially in China), so the connection fails outright, regardless of any acceleration proxy. The launcher automatically disables this check for its own bundled Git (system git is untouched; download integrity is still enforced by mandatory sha256/Authenticode verification). If you hit this with an older launcher version or a manually installed git, run once: `git config --system http.schannelCheckRevoke false`, then deploy again.

### Q16: Launching WebUI fails with "ImportError: Failed to initialize: Bad git executable"
The bundled Git is not on the system PATH, so it relies on environment variables; Forge (Neo)'s webui.bat copies the value of the GIT variable **verbatim** into GitPython's `GIT_PYTHON_GIT_EXECUTABLE`. If the path contains spaces and the GIT value is wrapped in quotes, GitPython treats the quote characters as part of the file path and fails to initialize. New launcher versions always inject the raw unquoted path. If you hit this on an older version, update the launcher, or move the deploy directory to a pure-English path without spaces.

### Q17: Dependency install fails with externally-managed-environment / "managed by uv"
Your system Python is managed by a tool like uv, which forbids pip from installing into it (PEP 668) — every mirror fails with the same error, and it's not a network problem. Update the launcher to the latest version: the start bat never touches the system Python anymore — it downloads a portable Python and installs dependencies into a project-local `.venv` virtual environment (venvs are exempt from externally-managed restrictions), so the setup is identical on every PC.

### Q18: How do I update the launcher itself?
Open the "Launcher update" card at the top of the Advanced settings page → Check for updates → Update now → restart. No need to re-download the whole ZIP: git clones pull only the changed commits, ZIP installs get an overlay update; your config, portable Python/Git, WD14 environment and model caches are all preserved. The current version is shown under the sidebar logo (format: 2.0.commit-count, auto-incremented on every update).

├─ config_manager.py      ← config, command-line generation

Just cut/copied the whole Forge directory (including python/, git/, venv/) to a new location — the launcher automatically fixes the old paths recorded in the venv on every launch.
