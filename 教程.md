## 一、开始前：你需要准备什么

| 项目 | 要求 |
|---|---|
| 电脑系统 | Windows 10（1803 以上）或 Windows 11，64 位 |
| 显卡 | 最好是 NVIDIA 显卡，显存 6GB 以上体验较好；4GB 也能跑（低显存模式）；没有独显可以纯 CPU 跑，但非常慢 |
| 硬盘空间 | 至少预留 **25GB**——Forge 本体加依赖约 10GB，一个大模型 2~7GB |
| 网络 | 能正常上网即可。国内用户启动器会自动走镜像加速，不用手动设置 |
| 要装什么软件吗 | **什么都不用装**。Python、Git 全部由启动器自动下载便携版 |

还有一样东西要准备：**耐心**。第一次部署要下载好几个 GB，视网速 10 分钟到 1 小时，中途可以关，下次接着来。

## 二、三分钟名词扫盲

看懂这几个词，后面就不懵了：

- **Stable Diffusion（SD）**：一个开源的 AI 画图引擎，输入文字描述（提示词）就能生成图片
- **WebUI**：给 SD 套的网页操作界面，在浏览器里点按钮画图，不用敲代码
- **Forge**：WebUI 的一个优化分支，速度快、显存占用低。本启动器就是给它做的"一键安装+启动"工具
  - **Neo 版**：社区持续维护的新分支（支持 40/50 系新显卡），**新用户一律用它**
  - **常规版 / Classic**：官方原版，已停止更新
- **大模型 / Checkpoint**：AI 的"画风大脑"，一个 2~7GB 的文件（`.safetensors`），没有它画不了图
- **LoRA**：小型"补丁"模型，给大模型追加特定人物/画风，通常几十到几百 MB
- **提示词（Prompt）**：描述你想要画面的英文词组，如 `1girl, school uniform, cherry blossoms`
- **反推 / 打标签（WD14）**：反过来，给一张图让 AI 写出它的提示词，主要用来给 LoRA 训练集打标

## 三、第一步：下载并解压启动器

1. 打开本仓库主页 → 点绿色 **Code** 按钮 → **Download ZIP**
2. 解压下载到的压缩包。解压位置**非常重要**：
   - ✅ 推荐：`D:\forge-launcher`、`E:\AI\launcher` 这种**纯英文路径**
   - ❌ 避免：桌面（路径含中文用户名）、路径里带空格、`(1)` 这种括号
   - 路径带中文或括号是绝大多数"莫名报错"的根源（这是 Windows 命令行自身的限制，详见 [FAQ Q4](#q4部署时提示此时不应有-x或xxx-不是内部或外部命令)）
3. **不要直接在压缩包里双击运行**，一定要先完整解压

> 会用 git 的话也可以 `git clone https://github.com/wangjue520/forge-webui-launcher.git`，效果一样，以后更新还更快。

## 四、第二步：第一次双击 bat

双击 `start一键启动.bat`，会弹出一个黑色命令行窗口，自动完成这些事（**不用你操作，看着就行**）：

1. 检查启动器自己的运行环境，没有就自动下载一个免安装的便携版 Python 3.13（约 30MB，带官方哈希校验）
2. 创建启动器专用的虚拟环境 `.venv`，自动安装它需要的两个小组件
3. 全程不碰你系统里已装的任何 Python，也不会往系统里写东西

第一次约 1~3 分钟。遇到网络抖动启动器会**自己等几秒重试**，不用管；如果失败它会打印原因，一般再双击一次就好。

装完会弹出启动器窗口（深色界面、左侧一排按钮）。

- **窗口白屏**：极少数精简版系统缺 WebView2 运行时，装一下微软官方的即可（免费）：https://developer.microsoft.com/microsoft-edge/webview2/
- 界面太大/太小：**Ctrl + 滚轮**缩放，会自动记住

> ⚠️ 注意：此时只是"启动器"装好了，**画图的 Forge 本体还没有**，继续下一步。

## 五、第三步：部署 Forge WebUI

> 只有第一次需要这一步，以后永远不用再来。

1. 点左侧 **「环境部署」**
2. **分支**保持默认的 `Neo 版（Haoming02 社区维护分支，推荐）`，不用改
3. **安装目录**点「浏览…」选一个空位置，例如 `D:\forge`
   - 必须是**空目录或不存在的目录**（同样强烈建议纯英文路径）
   - 如果你电脑里已经有秋叶整合包等现成 Forge，也可以直接选它的目录，会自动识别、跳过下载源码
4. 保持勾选 **「自动下载便携版 Python + Git」**（默认开着）——这样 Forge 用的 Python 和 Git 也装进 `D:\forge`，完全不污染系统
5. 点 **「开始部署」**，之后全自动，日志区会实时滚动：

| 阶段 | 在干什么 | 大概多久 |
|---|---|---|
| 便携环境 | 下载 Python + Git（约 100~150MB），校验哈希和签名后解压 | 1~5 分钟 |
| 拉取源码 | 从 GitHub 克隆 Forge（Neo 分支），连不上会自动换加速代理 | 1~5 分钟 |
| 安装依赖 | Forge 自己下载 torch 等好几个 GB 的依赖 | **10 分钟~1 小时** |
| 验证 | 自动把 WebUI 起起来跑一遍，确认能正常启动后自动关掉 | 1~2 分钟 |

- 装依赖阶段**没有进度条**，只有日志和每 30 秒一行的心跳提示（"仍在执行…"），这是正常的，不是卡死
- 随时可以点「取消」；网络断了、手滑关了都没关系——**再点一次「开始部署」就会从断点继续**，已经下好的部分不会重下
- 看到日志末尾 **「全部完成！」** 并弹出"部署完成"窗口 → 点「去一键启动」

### 部署出错怎么办

- 红色报错里带**超时/连接重置/503/504**：网络问题，直接再点一次「开始部署」
- 其他红字：对照 [FAQ](#十二常见问题-faq)，还不行就把最后 20 行日志截图发 Issue

## 六、第四步：下载一个大模型

没有大模型画不了图，先下一个：

1. 去 [Civitai](https://civitai.com)（国外最大模型站）或 [哩布哩布](https://www.liblib.art)（国内站，不用翻墙）挑一个喜欢的 Checkpoint 大模型，复制它的网页链接
2. 回到启动器，打开 **「模型下载」** 页
3. 把链接粘进输入框 → 点 **「获取信息」**（哩布哩布第一次用需要配 token，见下文）
4. 选好文件后，「保存位置」会**按模型类型自动填好**对应的文件夹，不用你懂目录结构
5. 点 **「下载并放入对应文件夹」**，等进度条走完

- 支持**断点续传**：下到一半断了，重新下一次会接着来
- 下完会自动校验文件完整性，并顺手把封面图、触发词等信息也存好
- **哩布哩布必须登录才能下载**：在浏览器登录哩布哩布 → 按 F12 → 应用（Application）→ Cookies → 复制 `usertoken` 的值 → 粘贴到「模型下载」页的输入框 → 点「验证并保存」。凭证只存在你自己电脑上
- Civitai 普通模型不用填 Key 直接下；只有下载受限内容才需要在 Civitai 网站生成 API Key 填进来

> 也可以不用启动器：自己下载 `.safetensors` 文件，手动放进 [模型目录对照表](#九模型目录对照表) 里对应的文件夹，效果一样。

## 七、第五步：启动并画出第一张图

1. 打开 **「一键启动」** 页（WebUI 根目录部署完已自动填好）
2. 点 **「启动」**
   - 启动前会自动做一轮检查，如果弹出提示框，照它说的选就行（各弹窗含义见 [一键启动页详解](#1一键启动页)）
3. 日志滚动一阵后，出现 `Running on local URL` ——浏览器会**自动打开** WebUI 网页
4. 网页左上角 **「Stable Diffusion checkpoint」** 下拉里选中你刚下的大模型
5. 在提示词框里输入：`1girl, school uniform, cherry blossoms, masterpiece, best quality`
6. 点右侧橙色的 **「生成 / Generate」**，等进度条走完——**你的第一张图诞生了** 🎉

生成的图片自动存在 Forge 目录下的 `output\txt2img-images\` 里。启动器「一键启动」页有一排「输出目录」按钮，点一下就能直接打开当天的出图文件夹。

想关掉：先在启动器点 **「停止」**（会把整个进程树干净地杀掉，不留占端口/显存的僵尸进程），再关窗口。WebUI 还在跑就直接关窗口的话，会弹确认框防止误关。

## 八、启动器全功能详解（八个页面）

### 1. 一键启动页

日常使用的主页面：

- **WebUI 根目录**：Forge 所在的文件夹，部署成功后自动填好；也可以手动「浏览…」指向秋叶整合包等已有安装
- **Python 解释器 / Git**：留空就行，会自动检测目录下的便携版，下方灰字实时显示检测结果；只有玩整合包的特殊情况才需要手动指定
- **启动参数预览**：显示实际会传给 Forge 的命令行参数（在「高级选项」页配置，这里只读）
- **自动打开浏览器开关**（默认开）：检测到 WebUI 就绪后自动开网页。注意就绪判定是双通道的——既解析日志、也探测端口，就算日志被整合包重定向了也能可靠识别
- **输出目录按钮组**：输出目录 / 文生图 / 当天文生图 / 图生图 / 当天图生图，一键打开对应文件夹（自动适配你在 WebUI 里改的出图目录和"按日期分目录"设置）

**点「启动」时可能遇到的弹窗：**

| 弹窗 | 意思 | 怎么选 |
|---|---|---|
| 检测到残留进程 | 上次 WebUI 没退干净，端口被占 | 「结束并启动」 |
| 检测到配置冲突 | 整合包的 webui-user.bat 写死了旧配置，会覆盖启动器的设置 | 「清空并启动」（原文件自动备份 .bak） |
| 路径含中文/空格 | 部分依赖有历史 bug | 建议换纯英文路径，也可以先继续试试 |
| --listen + 允许网页装扩展 | 局域网里任何人都能往你电脑装代码，危险 | 至少关掉一个 |

### 2. 高级选项页

所有设置**改动即自动保存**，没有保存按钮，下次启动 WebUI 时生效。

- **启动器更新**（页面顶部）：自动检查新版本；「立即更新」只升级启动器自身代码，你的配置、模型、环境全部保留，更新完点「重启启动器生效」
- **当前所属分支**：决定参数体系（Neo 新参数 / Neo 旧参数 / Classic），部署后自动填对，一般不用动
- **性能设置**：GPU 编号、显存策略、计算精度、注意力加速库（xFormers/Flash/Sage）等——**小白全部保持"自动"**，Forge 会自己管显存；需要手动调的场景见 [第十节](#十启动参数怎么选显存精度)
- **网络与其他**：局域网访问、API、公网分享、端口（默认 7860）、自定义追加参数、网页主题等
- **下载加速**：自动检测（推荐）/ 总是镜像 / 总是官方源；挂了梯子建议选"自动"或"总是官方源"
- **仅供参考**区：GPU Weight、共享显存回退等选项**不生成任何参数**，只是记录+指路——真正生效要去 WebUI 网页里的 Settings 设置

### 3. 环境部署页

除了首次部署（见 [第五步](#五第三步部署-forge-webui)），还有几个"维修工具"：

- **重新检测**：重跑系统 Git/Python 环境检查
- **检测该目录**：检查你选的目录里是什么（已有安装 / 上次部署残留可续跑 / 非空目录不能用）
- **检测现有 venv 版本**：venv 和当前分支要求的 Python 版本不符时，按提示删除重建
- **写入 hashlib 兼容补丁**：遇到 `hashlib has no attribute 'file_digest'` 报错时点这个，不用重装

把 Forge 目录整个剪切搬家也没问题——启动器每次启动前会自动修正 venv 里记录的旧路径。

### 4. 模型下载页（C 站 · liblib）

- 粘贴 Civitai 或哩布哩布的模型页链接（也支持版本链接、纯 ID）→「获取信息」→ 选文件 →「下载并放入对应文件夹」
- 保存位置按模型类型**自动填好**（大模型→Stable-diffusion、LoRA→Lora、VAE→VAE……），前提是「一键启动」页已设好根目录
- 断点续传；下完自动 SHA256 校验——校验不过的文件会被改名成 `.broken` 保留，不会被当成正常模型加载
- 下完自动写入模型信息（触发词等）和封面预览图，「模型管理」页直接就能看
- 哩布哩布强制登录，必须先配 usertoken（见 [第六步](#六第四步下载一个大模型)）

### 5. 模型管理页

给已经下载的模型做"档案管理"：

- 左侧按类别浏览（大模型/LoRA/VAE/Embedding/ControlNet/放大模型……），支持关键字过滤、按基础模型筛选、点表头排序
- 鼠标悬停任意一行，直接 **定位文件 / 复制名称 / 复制 LoRA 调用格式**，不用点开
- **哈希查询补全信息**：按文件的 SHA-256 哈希去 Civitai（查不到再查 liblib）精准匹配，自动写回触发词、封面图、基础模型信息；单个查或「一键查询本类别」批量补全都行（大模型算哈希要几十秒，正常）
- 详情区可以**手动编辑触发词**（手动填的永远不会被站点查询覆盖）、手动绑定 liblib 链接
- 「删除该模型…」会把模型连同它的封面图、信息文件一起删除（有确认框，不可恢复）

| Attention Couple | 分区控制画面（两个分支都能用） |

### 7. WD14 反推页

给图片自动打标签（训练 LoRA 的必备工序），是启动器内置的独立工具，**不依赖 WebUI、不装扩展也能用**：

1. 首次使用先点 **「加载模型」**：自动下载模型（默认 wd-vit-tagger-v3，约 380MB，国内走 hf-mirror 镜像、支持断点续传）并部署独立的 Python 环境 `wd14_venv`，与 Forge 环境完全隔离
2. 把图片**拖进列表框**（也可点「选择图片…」「选择文件夹（批量）…」，甚至 **Ctrl+V 直接粘贴截图**）
3. 点 **「开始反推」**：每张图输出一串逗号分隔的标签
4. 默认勾选「批量处理时保存为同名 .txt」——标签直接写在每张图片旁边，就是 LoRA 训练需要的格式
5. 两个阈值滑块：常规标签 0.35、角色标签 0.85，默认值适合大多数情况
6. 想要更高精度：模型下拉里换 `wd-eva02-large`（更大更慢更准）；镜像也下不动时可用「手动导入模型…」

### 8. 图片信息页

把 AI 生成的图拖进来，读出它当时用的全部参数：

- 支持 **PNG / JPG / WebP**，甚至 ComfyUI 工作流 `.json` 文件；也能 **Ctrl+V 粘贴截图**
- 识别来源非常广：A1111 / Forge / reForge、ComfyUI（会真正遍历工作流节点图，还原提示词链和 LoRA 链）、NovelAI V3–V5（含多角色提示词）、Fooocus / SwarmUI / InvokeAI / Draw Things，甚至参数藏在像素里的隐写图、LoRA 训练集的同名 txt
- 解析结果：正向/负向提示词、角色提示词（NovelAI 多角色）、LoRA 列表（一键复制 `<lora:名字:强度>` 调用格式）、Civitai 资源链接（直接跳模型页）、采样器/步数/CFG/种子等参数表
- **缺失模型检测**：解析 ComfyUI 工作流时，自动对照你本地的模型文件夹，标出哪些模型你还没有；带哈希的精确反查 Civitai 并可勾选直接下载，无哈希的可以按名字搜索（弹窗列候选，由你人工确认，不会乱下）
- 底部三个复制按钮：复制正向 / 复制负向 / 复制全部原始参数（可直接粘进 WebUI 的 PNG Info 里复现）

> 最常见的"读不出来"：图片经过微信/QQ 传输或网站二次压缩后元数据被抹掉了，这不是启动器的问题。

## 十、启动参数怎么选（显存/精度）

在 **「高级选项」** 页配置，所有选项会实时预览生成的命令行参数。

**普通用户全部保持"自动"即可**，Forge 会自动管理显存。只有遇到问题时才动：

| 症状 | 试试 |
|---|---|
| 显存不够、报 OOM（8GB 以下显卡常见） | 显存策略选「低显存 / lowvram」；Neo 版再把 VAE 精度选 BF16 |
| 出图全黑/全灰 | 计算精度选「全部使用 FP32」，或把 VAE 放 CPU |
| 40/50 系显卡想压榨性能 | Neo 版专属的 `--fast-fp16`、`--expandable-segments` 开关 |
| 显存被吃满导致桌面卡死 | Neo 版「预留显存」填 1~2（GB） |

注意 Forge 有两套互不兼容的参数体系（Neo 新参数 `--normalvram`/`--force-fp16` 等，Classic/旧 Neo 用 `--always-xxx-vram`/`--all-in-fp16`），启动器会按分支自动生成对的，不需要你背。

## 十一、国内网络加速与下载安全

启动器自动探测网络环境（可在「高级选项」页重新检测或强制指定）：

| 环节 | 加速方式 |
|---|---|
| GitHub 下载/克隆 | 自动走加速代理（多个候选逐个试），原站兜底 |
| pip 依赖 | 清华 → 阿里云 → 官方源逐个尝试 |
| torch（几个 GB） | 部署时由启动器**外置预下载**（断点续传 + sha256 校验 + 上海交大/清华/官方按序轮换），装好后 Forge 自动跳过自己的安装；同时注入 `TORCH_INDEX_URL` 镜像兜底 |
| HuggingFace 模型 | 自动切 hf-mirror.com |

**下载安全**：凡是经加速代理下载的二进制（Python/Git/源码），一律做**强制来源校验**——哈希基准取自官方 release 的校验清单并与 GitHub API 交叉核对，解压/执行前强制比对 sha256，Git 安装包还额外验微软 Authenticode 数字签名。校验不过自动换地址重下，全部不符宁可中止也绝不执行来源不可证的东西。所以看到"校验失败"中止，说明当前网络链路有问题，换个网络/代理再试。

## 十二、常见问题 FAQ

### Q1：双击 bat 后等很久/失败，再双击又好了
便携 Python 下载走的加速代理偶尔会抖动。新版启动器遇到这种情况会**自己等几秒自动重试**；如果你用的是旧版，更新一下启动器（「高级选项」页顶部）即可。反复失败就先挂好代理/加速器再双击。

### Q2：窗口白屏或提示 WebView2 错误
系统缺少 Edge WebView2 运行时（极少数精简版系统）。装一下微软官方的即可（免费、无需登录）：
https://developer.microsoft.com/microsoft-edge/webview2/

### Q3：双击 bat 一闪而过 / 提示"不是内部或外部命令"
把启动器放到**纯英文路径**再试；不要从压缩包里直接运行，先完整解压。

### Q4：部署时提示"此时不应有 X"或"XXX 不是内部或外部命令"
安装路径里有 `()`、`&`、`^`、`%`、`!` 等字符（常见：浏览器重复下载导致文件夹名带 `(1)`）。
**换纯英文路径**（如 `D:\forge`）重新部署即可，这是 Windows 命令行自身的限制。

### Q5：启动 WebUI 时报错端口被占用 / 7860 被占
上次 WebUI 没退干净。启动时的预检弹窗里选「结束并启动」；或重启电脑。

### Q6：提示 venv 版本不一致 / "Requires-Python >=3.x"
venv 是旧 Python 建的，跟当前分支要求不符。到「环境部署」页点「检测现有 venv 版本」→「删除 venv」，下次启动会自动用正确的 Python 重建。

### Q7：加载模型时报 "hashlib has no attribute file_digest"
老 venv 缺 Python 3.11 的新方法。「环境部署」页点「写入 hashlib 兼容补丁」即可，不用重装。

### Q8：模型下载页提示"用户未登录"（哩布哩布）
哩布哩布的下载接口强制登录。在浏览器登录哩布哩布 → F12 → 应用（Application）→ Cookies → 复制 `usertoken` 的值 → 粘贴到「模型下载」页的输入框 →「验证并保存」。

### Q9：torch 下载到一半断了
直接再点「开始部署」。pip 自带断点续传，已下载的进度不会丢，所有镜像源会自动轮着试。

### Q10：装好了但网页没自动打开 / 一直"启动中"
看「一键启动」页的状态灯和日志：
- 日志里有 `Running on local URL: http://127.0.0.1:7860` 但没开浏览器 → 点页面上的「在浏览器中打开」，或手动复制地址
- 有红字报错 → 把最后 20 行截图发 Issue

### Q11：杀软报毒 / 文件被删
便携 Python/Git 是从官方 release 原站下载的（带哈希+签名校验），但国产杀软可能误报、或扫描刚落地的文件导致首次启动失败。把启动器目录和部署目录加入杀软白名单/排除列表后重试。

### Q12：如何更新 Forge 本体
「环境部署」页对已有目录再点一次「开始部署」即可——会跳过克隆直接更新依赖、验证可启动。Neo 分支的日常更新也可以直接在 WebUI 网页里用内置的更新功能。

### Q13：走加速代理下载的东西安全吗？会不会被篡改？
启动器对每一个经代理下载的二进制都做了**强制来源校验**，不通过就中止（宁可装不了，也不装来源不可证的东西）：

1. **哈希基准取自官方**：Python 用 python-build-standalone 每个 release 附带的 `SHA256SUMS` 清单，Git 用 git-for-windows 发布正文里的官方校验和，并与 GitHub API 的资产摘要交叉核对——两者不一致直接中止；
2. **解压/执行前强制比对 sha256**：下载完先校验，不符就自动换下一个候选地址重下，全部地址都不符则部署失败；
3. **Git 安装包额外验数字签名**：执行自解压包前用 Windows Authenticode 验证官方签名（Johannes Schindelin / git-for-windows），伪造的二进制过不了系统信任链。

### Q14：提示"没有可用的哈希校验基准，已中止（安全策略）"
是上面的安全机制在起作用：没能拿到官方校验清单（通常是网络把 GitHub API 和原站都挡住了）。换个网络环境/挂好代理后重新部署即可。

### Q15：拉取代码报 CRYPT_E_NO_REVOCATION_CHECK (0x80092012)，退出码 128
Windows 版 git 用系统 Schannel 建立加密连接，握手前要联网向证书颁发机构查询"证书有没有被吊销"——这个查询地址在很多网络环境（尤其国内）不可达，连接直接失败，和走不走加速代理无关。启动器部署时会自动关闭便携版 Git 的这个检查（只影响启动器自己那份 git；下载链路另有 sha256/Authenticode 强制校验兜底）。旧版启动器或手动装的 git 遇到此错误可执行一次：`git config --system http.schannelCheckRevoke false`，然后重新部署。

### Q16：启动 WebUI 报 "ImportError: Failed to initialize: Bad git executable"
便携 Git 不在系统 PATH 里，要靠环境变量指路；而 Forge（Neo）的 webui.bat 会把 GIT 变量的值**原样**拷给 GitPython。路径一旦带空格、GIT 值又加了引号，GitPython 会把引号当成路径的一部分去执行。新版启动器已改为始终注入未加引号的原始路径；旧版遇到请升级启动器，或把部署目录换到纯英文无空格路径。

### Q17：装依赖时报 externally-managed-environment / "managed by uv"
你的系统 Python 是 uv 等工具托管的，按 PEP 668 规则禁止 pip 直接装包——这不是网络问题。更新到最新版启动器即可：启动 bat 完全不碰系统 Python，自动下载便携版 Python 装进项目内 `.venv`（venv 不受此限制），任何电脑上环境一致。

### Q18：启动器自己怎么更新？
「高级选项」页顶部的「启动器更新」卡片 →「检查更新」→「立即更新」→「重启启动器生效」。不用重新下载压缩包：git 克隆安装的只拉取变化的提交，ZIP 安装的走整包覆盖；你的配置、便携 Python/Git、WD14 环境和模型缓存全部原样保留。当前版本号显示在侧边栏 logo 下方。

### Q19：生成的图片存在哪？
默认在 Forge 目录下的 `output\txt2img-images\`（文生图）和 `output\img2img-images\`（图生图）；Classic 分支是 `outputs\`（复数）。开了"按日期分目录"的话下面还有一层日期文件夹。最快的办法：点「一键启动」页的「当天文生图」按钮直接打开。

### Q20：自动部署反复失败，有没有手动方案？
有。下载完整的 Forge Neo 整合包（百度网盘）：https://pan.baidu.com/s/1SV-YxTe-5DhA4PPjDk-neQ?pwd=26u8 （提取码 `26u8`），解压后在「环境部署」页的「安装目录」里选择解压出来的文件夹，再点一次「开始部署」——检测到已有安装会自动跳过源码下载，只补齐环境。部署失败时的弹窗里也会给出这个链接。

## 1. Before you start: what you need

| Item | Requirement |
|---|---|
| OS | Windows 10 (1803+) or Windows 11, 64-bit |
| GPU | NVIDIA recommended, 6GB+ VRAM for a good experience; 4GB works (low-VRAM mode); CPU-only is possible but very slow |
| Disk space | At least **25GB** — Forge plus dependencies take ~10GB, and one checkpoint is 2–7GB |
| Network | Any working connection. Users in China get automatic mirror acceleration, no manual setup |
| Software to install | **Nothing.** Python and Git are downloaded as portable builds by the launcher itself |

Also bring **patience**: the first deployment downloads several GB — 10 minutes to 1 hour depending on your network. You can cancel anytime; it resumes where it left off.

## 2. A 3-minute glossary

- **Stable Diffusion (SD)**: an open-source AI image engine — you give it a text description (a *prompt*), it generates an image
- **WebUI**: a browser-based interface for SD — click buttons instead of typing code
- **Forge**: an optimized fork of WebUI — faster, lower VRAM usage. This launcher is a one-click installer/starter for it
  - **Neo**: the actively community-maintained branch (supports newer 40/50-series GPUs) — **new users should always pick it**
  - **Classic**: the original official release, no longer updated
- **Checkpoint**: the AI's "artistic brain" — a 2–7GB `.safetensors` file. No checkpoint, no images
- **LoRA**: a small "patch" model that adds a specific character/style on top of a checkpoint, usually tens to hundreds of MB
- **Prompt**: English phrases describing the image you want, e.g. `1girl, school uniform, cherry blossoms`
- **WD14 tagging**: the reverse — show AI an image and it writes the prompt tags for you; mainly used to label LoRA training sets

## 3. Step 1: Download and extract the launcher

1. Open the repository page → green **Code** button → **Download ZIP**
2. Extract the archive. The location **matters a lot**:
   - ✅ Good: pure-English paths like `D:\forge-launcher`, `E:\AI\launcher`
   - ❌ Avoid: the Desktop (Chinese username in path), spaces, folder names with `(1)`
   - Chinese characters or parentheses in the path cause ~90% of mysterious errors (a Windows cmd limitation — see [FAQ Q4](#q4-deploy-fails-with-x-was-unexpected-at-this-time))
3. **Do not run it from inside the ZIP** — extract fully first

> If you know git: `git clone https://github.com/wangjue520/forge-webui-launcher.git` works too, and updates are faster afterwards.

---

## 4. Step 2: The first double-click

Double-click `start一键启动.bat`. A black console window appears and automatically (you don't touch anything):

1. Checks the launcher's own runtime; if missing, downloads a portable Python 3.13 (~30MB, verified against official hashes)
2. Creates the launcher's private virtual environment `.venv` and installs its two small dependencies
3. Never touches any Python already on your system, and writes nothing system-wide

The first run takes 1–3 minutes. On network hiccups the launcher **waits a few seconds and retries by itself**; if it fails it prints the reason — usually a second double-click finishes the job.

Then the launcher window pops up (dark UI, buttons on the left).

- **White window**: rare stripped-down systems lack the WebView2 runtime — install Microsoft's official one (free, no login): https://developer.microsoft.com/microsoft-edge/webview2/
- UI too big/small: **Ctrl + mouse wheel** to zoom; the level is remembered

> ⚠️ At this point only the *launcher* is installed — **Forge itself is not**. Continue to the next step.

## 5. Step 3: Deploy Forge WebUI

> You only do this once, ever.

1. Click **环境部署 (Deploy)** in the left sidebar
2. Keep **Branch** on the default `Neo 版 (Haoming02 community branch, recommended)`
3. Click **浏览… (Browse)** next to **Install directory** and pick an empty location, e.g. `D:\forge`
   - Must be an **empty or non-existent directory** (pure-English path strongly recommended)
   - If you already have a Forge bundle (e.g. a Chinese community repack), you can point at its directory — it will be detected and source download is skipped
4. Keep **自动下载便携版 Python + Git (auto-download portable Python + Git)** checked (default) — Forge's Python and Git go into `D:\forge` too, leaving your system untouched
5. Press **开始部署 (Start deploy)**. Everything is automatic from here, with a live scrolling log:

| Stage | What happens | Roughly |
|---|---|---|
| Portable env | Downloads Python + Git (~100–150MB), verifies hash and signature, extracts | 1–5 min |
| Source code | Clones Forge (Neo branch) from GitHub; auto-switches to acceleration proxies if needed | 1–5 min |
| Dependencies | Forge downloads several GB of dependencies including torch | **10–60 min** |
| Verification | Briefly starts WebUI to prove it works, then shuts it down | 1–2 min |

- The dependency stage has **no progress bar** — only the log and a heartbeat line every 30 seconds ("still running…"). That's normal, not a freeze
- You can press **取消 (Cancel)** anytime; if the network drops or you close it by accident, **just press Start deploy again — it resumes from where it stopped**
- When the log ends with **全部完成！(All done!)** and a completion dialog appears → press **去一键启动 (Go to launch)**

### If deployment fails

- Red errors mentioning **timeout / connection reset / 503 / 504**: network issue — press Start deploy again
- Other red text: check the [FAQ](#12-faq); if stuck, open an Issue with a screenshot of the last 20 log lines

## 6. Step 4: Download a checkpoint

No checkpoint, no images — grab one first:

1. On [Civitai](https://civitai.com) (largest international model site) or [liblib](https://www.liblib.art) (Chinese site), pick a Checkpoint you like and copy its page URL
2. In the launcher, open **模型下载 (Download)**
3. Paste the link → press **获取信息 (Fetch info)** (liblib requires a token on first use — see below)
4. Pick the file; the **save location is auto-filled** with the correct folder for that model type — no need to know the directory layout
5. Press **下载并放入对应文件夹 (Download into the matching folder)** and wait for the progress bar

- **Resume supported**: if a download breaks, downloading again continues from the breakpoint
- Integrity is verified (SHA256) after download; cover images and trigger words are saved automatically
- **liblib requires login**: log in to liblib in your browser → F12 → Application → Cookies → copy the `usertoken` value → paste it into the token field on the Download page → **验证并保存 (Verify & save)**. The token stays on your own PC
- Civitai needs no API key for normal models; only restricted content requires generating a key on the Civitai site

> You can also skip the launcher: download `.safetensors` files yourself and drop them into the right folder from the [model folder mapping](#9-model-folder-mapping).

## 7. Step 5: Launch and generate your first image

1. Open **一键启动 (Launch)** (the WebUI root directory is auto-filled after deployment)
2. Press **启动 (Launch)**
   - A preflight check runs first; if a dialog pops up, just follow its advice (see [Launch page](#1-launch-page-一键启动) for what each dialog means)
3. After some log scrolling, `Running on local URL` appears and your browser **opens WebUI automatically**
4. In the top-left **Stable Diffusion checkpoint** dropdown, select the checkpoint you downloaded
5. Type into the prompt box: `1girl, school uniform, cherry blossoms, masterpiece, best quality`
6. Press the orange **Generate** button, wait for the progress bar — **your first image!** 🎉

Images are saved under `output\txt2img-images\` in the Forge directory. The Launch page has a row of output-folder buttons — one click opens today's image folder.

To shut down: press **停止 (Stop)** in the launcher first (kills the whole process tree cleanly — no zombie processes holding ports/VRAM), then close the window. If you close the window while WebUI is still running, a confirmation dialog prevents accidents.

## 8. Full feature tour (eight pages)

### 1. Launch page (一键启动)

Your daily home page:

- **WebUI 根目录 (WebUI root)**: the folder containing Forge; auto-filled after deployment, or browse to an existing install (e.g. a community bundle)
- **Python 解释器 / Git**: leave empty — the portable copies inside the directory are auto-detected, with live detection status shown below. Only set these manually for unusual bundle setups
- **启动参数预览 (Argument preview)**: the exact command-line arguments passed to Forge (configured on the Advanced page; read-only here)
- **Auto-open browser toggle** (on by default): opens the page once WebUI is ready. Readiness detection is dual-channel — it parses the log *and* probes the port, so it works even when a bundle redirects the log output
- **Output folder buttons**: output root / txt2img / today's txt2img / img2img / today's img2img — one click opens the folder (adapts to custom output dirs and date-subfolder settings in WebUI)

**Dialogs you may see when pressing Launch:**

| Dialog | Meaning | What to pick |
|---|---|---|
| Leftover processes detected | Previous WebUI didn't exit; port occupied | "Kill and launch" |
| Config conflict detected | A bundle's webui-user.bat hardcodes variables that override the launcher | "Clear and launch" (original backed up as .bak) |
| Path contains Chinese/spaces | Some dependencies have historic bugs | Prefer a pure-English path; you can try continuing |
| --listen + insecure extension access | Anyone on your LAN could install code on your PC — dangerous | Turn at least one off |

### 2. Advanced page (高级选项)

Every setting here **auto-saves on change** (no save button) and applies to the next WebUI launch.

- **启动器更新 (Launcher update)** (top card): automatically checks for new versions; "Update now" upgrades only the launcher's own code — your config, models and environments are preserved; press "Restart launcher" afterwards
- **当前所属分支 (Branch)**: selects the parameter system (Neo new / Neo legacy / Classic); auto-filled after deployment, rarely needs touching
- **性能设置 (Performance)**: GPU index, VRAM policy, precision, attention accelerators (xFormers/Flash/Sage) — **beginners should leave everything on "Auto"**; see [section 10](#10-choosing-launch-parameters-vramprecision) for when to tweak
- **网络与其他 (Network & misc)**: LAN access, API, public share link, port (default 7860), custom extra arguments, web theme
- **下载加速 (Download acceleration)**: Auto (recommended) / always mirror / always origin; if you run a system proxy/VPN, choose Auto or Always-origin
- **仅供参考 (Info only)** section: GPU Weight, shared-memory fallback etc. **produce no arguments** — they only record preferences and point you to where the real setting lives inside WebUI's Settings

### 3. Deploy page (环境部署)

Besides first-time deployment ([step 3](#5-step-3-deploy-forge-webui)), there are repair tools:

- **重新检测 (Re-detect)**: re-runs the system Git/Python environment check
- **检测该目录 (Check this directory)**: tells you what's in the chosen folder (existing install / resumable leftover / non-empty unusable)
- **检测现有 venv 版本 (Check venv version)**: when the venv's Python doesn't match the branch requirement, offers to delete and rebuild
- **写入 hashlib 兼容补丁 (Apply hashlib patch)**: fixes `hashlib has no attribute 'file_digest'` without reinstalling

Moving the whole Forge directory elsewhere is fine — the launcher repairs the stale paths recorded in the venv on every launch.

### 4. Download page (模型下载, Civitai · liblib)

- Paste a Civitai or liblib model page link (version links and bare IDs work too) → **获取信息** → pick a file → **Download into the matching folder**
- The save location is **auto-filled by model type** (Checkpoint→Stable-diffusion, LoRA→Lora, VAE→VAE…) as long as the WebUI root is set on the Launch page
- Resume support; SHA256 is verified after download — failed files are renamed to `.broken` and kept aside, never loaded as normal models
- Model info (trigger words etc.) and cover preview images are written automatically — the Models page shows them immediately
- liblib enforces login — configure the usertoken first (see [step 4](#6-step-4-download-a-checkpoint))

### 5. Models page (模型管理)

"Record keeping" for everything you've downloaded:

- Browse by category on the left (Checkpoint/LoRA/VAE/Embedding/ControlNet/Upscaler…), with keyword filter, base-model filter, and sortable columns
- Hover any row for instant **Reveal in Explorer / Copy name / Copy LoRA syntax** — no need to open the entry
- **Hash-based info lookup**: matches files by SHA-256 against Civitai (then liblib), writing back trigger words, cover image and base-model info; single-model or one-click whole-category batch lookup (hashing a big checkpoint takes tens of seconds — normal)
- The details pane lets you **edit trigger words manually** (manual entries are never overwritten by site lookups) and manually bind a liblib link
- "Delete this model…" removes the model together with its cover image and info files (confirmation shown; not recoverable)

### 6. Extensions page (常用插件)

Check items → **安装选中项 (Install selected)** → **restart WebUI** afterwards. Installed ones are auto-skipped; the list adapts to your branch (extensions broken on Neo are hidden; ones needing special forks get the right fork automatically):

| Extension | What it does |

### 7. WD14 tagger page (WD14 反推)

Automatic image tagging (essential for LoRA training) — a standalone built-in tool that works **without WebUI and without extensions**:

1. First use: press **加载模型 (Load model)** — downloads the model (default wd-vit-tagger-v3, ~380MB, via hf-mirror in China with resume support) and sets up an isolated Python environment `wd14_venv`, fully separate from Forge
2. **Drag images into the list** (or use "select images"/"select folder", or even **Ctrl+V to paste a screenshot**)
3. Press **开始反推 (Start tagging)**: each image gets a comma-separated tag string
4. "Save results as same-named .txt" is on by default — tags are written next to each image, exactly the LoRA training format
5. Two threshold sliders: general tags 0.35, character tags 0.85 — defaults suit most cases
6. Want higher accuracy: switch to `wd-eva02-large` in the model dropdown (bigger, slower, better); if mirrors fail too, use **手动导入模型 (Import model manually)**

### 8. Image info page (图片信息)

Drop an AI-generated image in to read every parameter it was made with:

- Supports **PNG / JPG / WebP** and even ComfyUI workflow **.json** files; **Ctrl+V** pastes screenshots too
- Recognizes a wide range of sources: A1111 / Forge / reForge, ComfyUI (actually walks the workflow node graph, reconstructing prompt and LoRA chains), NovelAI V3–V5 (including multi-character prompts), Fooocus / SwarmUI / InvokeAI / Draw Things, even steganographic PNGs with parameters hidden in pixels, and same-named .txt files from LoRA training sets
- Results: positive/negative prompts, character prompts (NovelAI multi-slot), LoRA list (one-click copy of `<lora:name:weight>` syntax), Civitai resource links (jump straight to model pages), and the sampler/steps/CFG/seed parameter table
- **Missing-model detection**: when parsing ComfyUI workflows, compares against your local model folders and flags what you don't have; hashed entries are precisely matched on Civitai and can be downloaded directly, unhashed ones can be searched by name (candidates shown in a dialog for you to confirm — nothing is downloaded blindly)
- Three copy buttons at the bottom: copy positive / copy negative / copy all raw parameters (paste straight into WebUI's PNG Info to reproduce)

> The most common reason for "nothing read": the image went through WeChat/QQ or a website's recompression, which strips metadata — not the launcher's fault.

## 10. Choosing launch parameters (VRAM/precision)

Configure on the **高级选项 (Advanced)** page; every option previews the generated command-line arguments in real time.

**Regular users should leave everything on "Auto"** — Forge manages VRAM by itself. Only tweak when something goes wrong:

| Symptom | Try |
|---|---|
| Out of VRAM / OOM (common under 8GB) | VRAM policy "Low VRAM / lowvram"; on Neo also set VAE precision to BF16 |
| All-black/all-gray output | Precision "Force FP32", or put the VAE on CPU |
| Squeezing a 40/50-series GPU | Neo-only toggles like `--fast-fp16`, `--expandable-segments` |
| Desktop freezes when VRAM maxes out | Neo-only "Reserved VRAM" set to 1–2 (GB) |

Note Forge has two mutually incompatible parameter systems (Neo new-style `--normalvram`/`--force-fp16` etc., Classic/legacy-Neo `--always-xxx-vram`/`--all-in-fp16`); the launcher generates the right set for your branch automatically.

## 11. Network acceleration for users in China & download security

The launcher auto-detects the network environment (re-detect or override on the Advanced page):

| Stage | Acceleration |
|---|---|
| GitHub downloads/clones | Auto via acceleration proxies (multiple candidates tried in turn), origin as fallback |
| pip dependencies | Tsinghua → Aliyun → official, tried in order |
| torch (several GB) | Pre-downloaded by the launcher itself at deploy time (resumable + sha256-verified, SJTU/Tsinghua/official tried in order); once installed, Forge skips its own install. `TORCH_INDEX_URL` mirror injection remains as fallback |
| HuggingFace models | Auto-switched to hf-mirror.com |

**Download security**: every binary fetched through a proxy (Python/Git/source code) undergoes **mandatory origin verification** — hash baselines come from official release checksum manifests cross-checked against the GitHub API, sha256 is enforced before extraction/execution, and the Git installer additionally passes Windows Authenticode signature validation. A failed check switches to another mirror; if none match, deployment aborts rather than running unverifiable binaries. So a "verification failed" abort means your current network path is faulty — switch networks/proxies and retry.

## 12. FAQ

### Q1: The first double-click takes forever/fails, the second works
The acceleration proxies used for the portable Python download occasionally hiccup. Current launcher versions **wait a few seconds and retry automatically**; if you're on an old version, update the launcher (top card of the Advanced page). If it keeps failing, enable your proxy/VPN and double-click again.

### Q2: White window or a WebView2 error
Your system lacks the Edge WebView2 runtime (rare, stripped-down Windows). Install Microsoft's official runtime (free, no login):
https://developer.microsoft.com/microsoft-edge/webview2/

### Q3: The bat flashes a console / "is not recognized as an internal or external command"
Move the launcher to a **pure-English path**; don't run it from inside the ZIP — extract fully first.

### Q4: Deploy fails with "X was unexpected at this time"
The install path contains `()`, `&`, `^`, `%`, `!` etc. (commonly a `(1)` suffix from repeated browser downloads).
**Switch to a pure-English path** (e.g. `D:\forge`) and deploy again — it's a Windows cmd limitation.

### Q5: Port occupied / 7860 already in use when launching
Previous WebUI didn't exit cleanly. Choose "Kill and launch" in the preflight dialog; or reboot.

### Q6: venv version mismatch / "Requires-Python >=3.x"
The venv was created by an older Python and doesn't match the current branch. On the Deploy page press "Check venv version" → "Delete venv"; it will be rebuilt with the correct Python on next launch.

### Q7: "hashlib has no attribute file_digest" when loading models
Old venvs lack a Python 3.11 addition. On the Deploy page press "Apply hashlib compatibility patch" — no reinstall needed.

### Q8: Downloader says "user not logged in" (liblib)
liblib's download API requires login. Log in to liblib in your browser → F12 → Application → Cookies → copy the `usertoken` value → paste it into the token field on the Download page → "Verify & save".

### Q9: torch download interrupted halfway
Just press Start deploy again. pip resumes downloads; all mirrors are tried automatically.

### Q10: Installed but the page didn't open / stuck "starting"
Check the status light and log on the Launch page:
- Log shows `Running on local URL: http://127.0.0.1:7860` but no browser opened → press "Open in browser" on the page, or copy the address manually
- Red errors → paste the last 20 lines into an Issue

### Q11: Antivirus flags / deletes files
The portable Python/Git come from official release sources (hash + signature verified), but some antivirus products false-positive, or scanning freshly written files makes the first launch fail. Add the launcher and deploy folders to the antivirus exclusion list and retry.

### Q12: How to update Forge itself
Press Start deploy again on the Deploy page with the existing directory — cloning is skipped and dependencies are updated/verified. On Neo you can also use the built-in updater inside the WebUI page for daily updates.

### Q13: Is downloading through acceleration proxies safe? Could files be tampered with?
Every binary downloaded via a proxy goes through **mandatory origin verification**; on failure the launcher aborts (it would rather fail than install something unverifiable):

1. **Hash baselines come from the official source**: Python uses the `SHA256SUMS` manifest shipped with every python-build-standalone release; Git uses the official checksum in the git-for-windows release notes, cross-checked against the GitHub API asset digest — any mismatch aborts immediately
2. **Mandatory sha256 check before extraction/execution**: on mismatch it auto-switches to the next candidate address; if none verify, deployment fails
3. **The Git installer additionally verifies the digital signature**: Windows Authenticode validation of the official signature (Johannes Schindelin / git-for-windows) before running the self-extractor — forged binaries can't pass the system trust chain

### Q14: "No available hash baseline, aborted (security policy)"
The security mechanism above is doing its job: it couldn't fetch the official checksum manifest (usually means the network blocks both the GitHub API and the origin site). Switch networks / set up a proper proxy and deploy again.

### Q15: Cloning fails with CRYPT_E_NO_REVOCATION_CHECK (0x80092012), exit code 128
Git for Windows uses the system Schannel for TLS, and before the handshake Windows must query the certificate authority online to check whether the server certificate has been revoked — that endpoint is unreachable in many networks (especially in China), so the connection fails regardless of any proxy. The launcher automatically disables this check for its own bundled Git only (system git is untouched; download integrity is still enforced by sha256/Authenticode verification). If you hit this with an older launcher or a manually installed git, run once: `git config --system http.schannelCheckRevoke false`, then deploy again.

### Q16: Launching WebUI fails with "ImportError: Failed to initialize: Bad git executable"
The bundled Git is not on the system PATH, so it relies on environment variables; Forge (Neo)'s webui.bat copies the GIT variable's value **verbatim** into GitPython's `GIT_PYTHON_GIT_EXECUTABLE`. If the path contains spaces and the GIT value is wrapped in quotes, GitPython treats the quotes as part of the path and fails. New launcher versions always inject the raw unquoted path. On older versions, update the launcher or move the deploy directory to a pure-English path without spaces.

### Q17: Dependency install fails with externally-managed-environment / "managed by uv"
Your system Python is managed by a tool like uv, which forbids pip installs (PEP 668) — not a network problem. Update the launcher: the start bat never touches the system Python anymore — it downloads a portable Python into a project-local `.venv` (venvs are exempt), so the setup is identical on every PC.

### Q18: How do I update the launcher itself?
Top card on the **高级选项 (Advanced)** page → Check for updates → Update now → Restart launcher. No need to re-download the ZIP: git clones pull only the changed commits, ZIP installs get an overlay update; your config, portable Python/Git, WD14 environment and model caches are all preserved. The current version is shown under the sidebar logo.

### Q19: Where are generated images saved?
By default under `output\txt2img-images\` (txt2img) and `output\img2img-images\` (img2img) in the Forge directory; on Classic it's `outputs\` (plural). With date subfolders enabled there's an extra date level. Fastest way: press the "Today's txt2img" button on the Launch page.

### Q20: Auto-deploy keeps failing — is there a manual option?
Yes. Download the complete Forge Neo bundle from Baidu Netdisk: https://pan.baidu.com/s/1SV-YxTe-5DhA4PPjDk-neQ?pwd=26u8 (extraction code `26u8`), extract it, then on the Deploy page point "Install directory" at the extracted folder and press Start deploy again — the existing install is detected, source download is skipped, and only the environment is completed. The failure dialog shows this link too.
