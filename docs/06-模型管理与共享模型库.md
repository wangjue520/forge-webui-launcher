## 一、「模型管理」页

侧栏「模型管理」，管理**当前实例**（侧栏顶部显示的那个）的所有模型。

### 页面布局

| 区域 | 说明 |
|---|---|
| 左侧分类 | Checkpoint 大模型、LoRA、VAE、Embedding、ControlNet、放大模型……（`models` 下其他有模型的文件夹会显示为「其他: 文件夹名」） |
| 顶部工具栏 | 刷新、一键查询本类别缺失信息、整理 LoRA、撤销上次整理 |
| 过滤 | 关键字过滤文件名；基础模型下拉框（只看 Illustrious / SDXL / …） |
| 列表 | 文件名、基础模型、大小、修改时间，**点表头排序** |
| 右侧详情 | 预览图、触发词、基础模型、来源等 |

### 常用操作

| 想做什么 | 怎么做 |
|---|---|
| 找某个 LoRA | 左边选 LoRA，上面输入关键字 |
| 看占硬盘最多的模型 | 点表头「大小」排序 |
| 在资源管理器里打开 | 鼠标悬停在那一行 → 📁 定位；或详情区「在资源管理器中定位」 |
| 复制 LoRA 调用格式 | 悬停 →「复制 lora 调用格式」，得到 `<lora:名字:1>`，粘到 WebUI 提示词里 |
| 复制文件名 | 悬停 →「复制文件名」（不含后缀） |
| 看触发词 | 选中 LoRA，右侧详情显示；**可以手动编辑**，手动填的永远不会被网上查询覆盖 |
| 删除模型 | 详情区「删除该模型…」，会连同预览图和 `.civitai.info` 一起删除，**不可恢复** |

### 补全模型信息（封面图、触发词）

自己从别处拷来的模型没有封面和触发词，启动器可以按文件内容（SHA-256 哈希）去网上查：

- **单个**：选中模型 → 详情区「哈希查询补全信息」
- **整个分类**：顶部「一键查询本类别缺失信息的模型」（可以随时「取消批量」）

先查 Civitai，查不到再查 liblib。查到后自动写入封面图和触发词。第一次算大模型的哈希需要几秒到几十秒。

> 查不到的情况：模型从来没在这两个站发布过、已被作者删除、或者文件被修改 / 合并过。

## 二、拖拽上传模型

别处下好的模型文件（网盘、群文件、浏览器下载的），不用自己找文件夹：

1. 「模型管理」左侧**先选好分类**（比如 LoRA）
2. 从资源管理器把文件**拖到页面上**（会出现「把模型文件拖到这里，即可上传到当前分类」）
3. 松手，自动复制进去

- 是**复制**，你原来的文件不动（确认没问题后可以自己删掉原文件省空间）
- 同一个文件已经有了会自动跳过；同名但内容不同会自动改名
- LoRA 开了自动整理的话，上传后会查信息并自动归类

## 三、LoRA 自动整理

LoRA 多了以后一堆文件堆在一起很难找。启动器可以按**底模**和**类型**自动分进子文件夹，比如：

```
models\Lora\
├─ Illustrious\
│   ├─ 角色\
│   ├─ 画风\
│   └─ 服装\
├─ SDXL\
│   └─ ……
└─ 未分类\
```

### 设置（「启动器设置 → LoRA 自动整理」）

| 选项 | 说明 |
|---|---|
| 新上传、新下载的 LoRA 自动归类 | 勾上后，以后下载 / 拖拽上传的 LoRA 查到信息就自动移进对应文件夹 |
| 文件夹结构 | 底模 / 类型（推荐）、类型 / 底模、只按底模、只按类型 |
| 手动整理时连已经在子文件夹里的也重新归类 | 默认不勾：只整理根目录和「未分类」里的，**不打乱你自己建的文件夹** |

### 手动整理已有的 LoRA

1. 「模型管理」→ 左侧选 **LoRA** →「**整理 LoRA**」
2. 先出**预览**：哪个文件会移到哪里，确认后再执行
3. 不满意 →「**撤销上次整理**」，全部搬回原处

整理后：
- Forge 网页的 Lora 标签页、ComfyUI 的 LoRA 下拉框都能按文件夹筛选
- **ComfyUI 已保存的工作流里的 LoRA 路径会自动同步改好**，不会因为挪了位置就找不到
- 提示词里的 `<lora:名字:1>` 不受影响（Forge 按文件名找，不看文件夹）

## 四、文件移动记录与撤销

「实例管理」页最下面「**文件移动记录**」：模型合并、LoRA 整理的每一批操作都有记录，点「撤销」就搬回原来的位置。

（合并时被判定为重复、放进回收站的文件，需要你自己去 Windows 回收站还原。）

## 五、多实例

一个「实例」= 一套 WebUI 或 ComfyUI 安装。比如你可以同时有：Forge Neo（日常出图）+ ComfyUI（跑工作流）+ H3 视频版。

### 添加实例

「启动器设置 → 多实例」勾上「显示多实例功能」，侧栏会出现「**实例管理**」页（添加第二个实例后会自动打开）。

- **添加已有安装**：登记电脑上现成的 WebUI / ComfyUI（整合包也行）
- **部署新的实例…**：进入部署流程，装完自动登记

### 实例卡片能做什么

改名、换根目录、设置单独端口、单独启动 / 停止、设为当前、移除（**只是从启动器里移除，不删文件**）。

### 「当前实例」是什么

侧栏顶部「当前实例」决定这几页操作的是谁：**一键启动、常用插件、模型管理**。
「高级选项」页有自己的实例选择器，改谁的设置不用切换当前实例。

### 同时运行

- 端口自动错开（WebUI 从 7860 开始、ComfyUI 从 8188 开始）
- 「一键启动」页顶部的状态卡片里每个实例都能单独启动 / 停止
- ⚠ 同一块显卡同时跑两个实例**很容易爆显存**，一般是一个用完停掉再开另一个

## 六、共享模型库

多个实例默认各有各的 `models` 文件夹，同一个大模型要存好几份，很占硬盘。共享模型库让所有实例共用一份。

### 开启

1. 「实例管理」→「共享模型库」→ 勾选「**开启共享模型库**」
2. 「浏览…」选一个**独立的文件夹**，比如 `D:\AI\models`
   - ⚠ **不要**选在任何实例的目录里面
3. 改了路径**直接生效**，下次启动实例时自动挂载

挂载方式：ComfyUI 通过 `extra_model_paths`，WebUI 通过 `--ckpt-dir`、`--lora-dir` 等启动参数，**不改动实例本身的任何文件**。关掉共享模型库，实例就恢复只看自己的 `models`。

### 把已有模型合并进模型库

1. **先停止所有实例**
2. 点「**合并各实例已有模型…**」
3. 先出**预览**：哪些模型会移进模型库、哪些是重复的
4. 确认「开始合并」

- 按**文件内容**判断重复（不是按文件名）：同一个模型在两个实例里各有一份，只留一份，多的放进回收站
- 合并后可以在「文件移动记录」里**撤销**

### 模型库的文件夹结构

模型库里按 ComfyUI 的命名方式分文件夹（`checkpoints`、`loras`、`vae`、`text_encoders`、`embeddings`、`controlnet`、`upscale_models`、`diffusion_models` …），Forge 和 ComfyUI 都能读。
开了模型库后，「模型下载」页下载的模型会直接放进模型库。
